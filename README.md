## What I do

I design and ship full stack products end to end — data model, backend, API surface, and
the interface people actually touch. The through-line in my work is software that stays
maintainable: clear module boundaries, real tests, and documentation an engineer can act on.

- **Backend & data** — serverless backends on Convex, relational modeling, REST APIs, integration layers
- **Frontend & mobile** — React and TypeScript on the web, Flutter for cross-platform mobile
- **Automation** — resilient pipelines, CLI tooling, and unattended browser automation
- **AI-assisted delivery** — LLM agents as part of the toolchain, driven by specs and verified by tests

<br>

## How I work

This changes the output more than any framework choice.

| Practice | What it means in my work |
| :--- | :--- |
| **Spec before code** | Requirements and acceptance criteria come first. No implementation starts from a vague ticket. |
| **Clean / Hexagonal architecture** | Domain logic stays independent of frameworks, so swapping infrastructure never rewrites business rules. |
| **Test-driven development** | Behavior is described by a failing test before the code exists. Coverage is a byproduct, not the goal. |
| **Agent-assisted, human-directed** | LLM agents execute under explicit direction and verification. The engineer owns the decisions; the agent owns the typing. |
| **Atomic design & container-presentational** | UI split by responsibility, so components stay composable and testable in isolation. |
